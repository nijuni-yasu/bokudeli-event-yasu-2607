## 本リリースの主な変更

`user` / `partner` / `support` / `enterprise` / `common`、Firestore Rules、インデックスに差分はない。画面・注文・決済・スキーマの機能追加はない。

| 領域 | 内容 | 参照 |
| --- | --- | --- |
| **管理画面 OGP** | `/manage/event/**` と `/manage/community/**` にタイトル・説明・カバー画像を出す。`noindex`。削除済み、または `enterprise_id` があるものは OGP なしの SPA | [#2082](https://github.com/nijuniinc/bokudeli-event-new/issues/2082) |
| **公開 OGP の失敗時** | イベント・コミュニティの OGP 生成で例外が出たとき、HTTP 500 ではなく取得済みの `index.html` を返す。`index.html` 自体が取れないときは 500 のまま。ログに status とエラー内容を残す | [#2163](https://github.com/nijuniinc/bokudeli-event-new/issues/2163) |
| **レターのテスト送信** | `sendTestLetter` はコミュニティ管理者だけが成功する。管理者以外は `permission-denied` | [#2442](https://github.com/nijuniinc/bokudeli-event-new/issues/2442) |
| **クライアントエラー通知** | 単体 `Failed to fetch` の dedup キーにユーザー ID を含める。ログレベルは ERROR のまま。1 件通知の除外と、10 分以内にログインユーザー 5 人以上の別アラートは Monitoring 側 | [#2174](https://github.com/nijuniinc/bokudeli-event-new/issues/2174) |
| **依存関係** | axios 1.20.0（#2434）。proxy-addr 2.0.8（#2436、ルートの overrides） | [#2434](https://github.com/nijuniinc/bokudeli-event-new/issues/2434) / [#2436](https://github.com/nijuniinc/bokudeli-event-new/issues/2436) |
| **Node.js** | `.node-version` を 24.19.0 から 24.22.1 にする。Functions の `engines.node` は 24 のまま | [#2481](https://github.com/nijuniinc/bokudeli-event-new/issues/2481) |
| **レガシー manager** | `manager/` を削除し、`firebase.json` から hosting の `manager` ターゲットを外す。既存の Hosting サイトは、この削除だけでは消えない | [#2482](https://github.com/nijuniinc/bokudeli-event-new/issues/2482) |

コミットの大半は競合調査、飲食店開催の検討、セキュリティ診断の記録、エージェント向け設定である。

## 実行順序の要点

```text
[0 ゲート] development の Deploy functions 成功
  → handleManageOgpRequest の存在
  → 管理画面 OGP、公開イベント、レターテスト送信の確認

[A 事前] 本番に人数指標と人数アラートを作る
  → 1件通知の filter はまだ変えない

[B 当日] release/2.15.0 を development にマージ
  → マージ後 HEAD にタグ v2.15.0
  → main / production / タグを push（production で本番デプロイ）
  → Functions 成功後に Deploy user を再実行する
  → 最後に 1件通知の filter から単体 Failed to fetch を外す

[C 後] 管理画面 OGP、公開イベント、レターテスト送信、両 workflow の成功を確認
```

## フェーズ B：当日

### B-1. バージョン PR

`development` から `release/2.15.0` を切り、ルートで `npm version minor --no-git-tag-version` を実行する（2.14.0 → 2.15.0）。このコマンドはタグもコミットも作らない。続けて `package.json` と `package-lock.json` をメッセージ `v2.15.0` でコミットし、`release/2.15.0` を push する。

`release/2.15.0` の PR が既にある場合は、ブランチを作り直さない。その PR をマージする。

- [ ] `release/2.15.0` → `development` の PR を merge commit でマージした
- [ ] マージ後に `git switch development && git pull origin development` で HEAD を確認した

### B-2. タグと本番 push

タグはマージ後の `development` HEAD に付ける。release ブランチ上のコミットには付けない。

```bash
git switch development && git pull origin development
git tag v2.15.0
git branch -f main development
git branch -f production development
git push origin main production v2.15.0
```

- [ ] タグ `v2.15.0` を付与し、`main` / `production` / タグを push した
- [ ] `development` は push していない（PR マージ済み）

この push で本番デプロイが始まる。

### B-3. CI で走るもの

`production` への push で、パスに当たる workflow が同時に走る。workflow 同士は待たない。`common/` は変わっていないため、`Deploy functions` 成功後の Hosting 自動起動は無い。

| Workflow | 発火理由 | 確認 |
| --- | --- | --- |
| Deploy functions | `functions/**` と `firebase.json` | 新規の `handleManageOgpRequest` を含む。success を待つ |
| Deploy user | `base/**`（axios） | `firebase.json` の `/manage/event/**` と `/manage/community/**` は user Hosting の rewrite。Function が未作成だと失敗する（#2202） |
| Deploy partner / enterprise / support | `base/**`（axios） | Function の完成を待たない。アプリのソース差分は無い |
| Deploy terms | `firebase.json` | 規約の本文は変わらない。terms ターゲットの再デプロイ。manage の rewrite はここではない |
| Deploy firestore / Deploy storage | 発火しない | Rules とインデックスは無変更 |

- [ ] `Deploy functions` が success
- [ ] `Deploy user` が Function 未作成で失敗した場合、Functions の success 後に `Deploy user` を再実行して success
- [ ] `Deploy partner` / `Deploy enterprise` / `Deploy support` / `Deploy terms` の成否を記録した
- [ ] `Deploy firestore` と `Deploy storage` は走っていない

`firebase deploy --only hosting:user` は `manager` ターゲットを更新しない。本番に残っている旧 manager サイトは、このリリースでは削除しない。
